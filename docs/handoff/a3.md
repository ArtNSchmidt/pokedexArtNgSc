# Handoff A3 — Adapter da PokéAPI

## O que entreguei

`apps/api/src/infrastructure/` — o **único** lugar do repositório que conhece `pokeapi.co`:

- `http/pokeApiClient.ts`: `PokeApiClient` (`fetch` nativo, `AbortSignal.timeout(8000)`; 404 → `PokemonNotFoundError`; rede/timeout/5xx/JSON inválido → `UpstreamUnavailableError`) e a porta de transporte `JsonHttpClient`.
- `cache/inMemoryTtlCache.ts`: `InMemoryTtlCache<T>` (TTL 86 400 s, limite de entradas com descarte do mais antigo, dedupe de requisições em voo); `cache/repositoryCaches.ts`: `createRepositoryCaches()` — um cache tipado por recurso.
- `pokeapi/schemas.ts`: schemas Zod do formato do terceiro (`z.looseObject`, só os campos do Anexo D); `{ name, url }` ganha `id` derivado da URL na validação.
- `pokeapi/mappers.ts`: funções puras DTO → contrato; chamam `@pokedex/domain` para fraquezas, evolução, texto e unidades.
- `pokeapi/pokemonIndex.ts`: índice da Pokédex nacional (ADR-003), carregamento idempotente e deduplicado.
- `pokeapi/pokeApiPokemonRepository.ts`: implementa `PokemonRepository` orquestrando os 6 endpoints.
- `pokeapi/upstream.ts`: `fetchParsed(client, path, schema)` — busca + validação na borda.
- `__fixtures__/*.json`: respostas reais gravadas em 2026-09-22 (`moves` e listas de Pokémon de habilidades removidos por não serem usados); `fakeJsonHttpClient.ts` serve-as offline.
- `pokeApi.learning.test.ts` (`describe.skip`): documenta o formato real; roda só localmente.

## O que exporto para os outros (símbolos, rotas, componentes)

`apps/api/src/infrastructure/index.ts`: `PokeApiClient`, `POKEAPI_BASE_URL`, `JsonHttpClient`, `InMemoryTtlCache`, `createRepositoryCaches`, `RepositoryCaches`, `PokemonIndex`, `PokeApiPokemonRepository`, `PokeApiPokemonRepositoryDeps`.

## Decisões que tomei e a alternativa que descartei

| Decisão                                                                                                          | Alternativa descartada e por quê                                                                                         |
| ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **Um cache tipado por recurso** (`RepositoryCaches`)                                                             | Um cache único `Map<string, unknown>`: a leitura exigiria `as T`, proibido em §5.1.                                      |
| `id` derivado de `url` **dentro do schema** (`transform` + `pipe`)                                               | Fazer parsing de string no mapper: URL sem id viraria `NaN` silencioso; agora é resposta inválida → 502.                 |
| `fetchParsed` trata resposta fora do schema como `UpstreamUnavailableError` (com caminho e primeira divergência) | Deixar o Zod lançar: a mensagem vazaria o formato do terceiro para o handler HTTP.                                       |
| Detalhe em duas fases: `Promise.all([espécie, habilidades, relações])` e depois cadeia → estágios                | Tudo em paralelo é impossível: a cadeia depende de `species.evolution_chain.url`.                                        |
| Estágios buscam `/pokemon/{speciesId}` (id de `species.url`)                                                     | Buscar pelo nome da espécie: `deoxys` não é um Pokémon (§2.3.4).                                                         |
| `spriteUrl` com fallback (artwork → URL canônica do repositório de sprites)                                      | Deixar o contrato falhar quando `front_default` é `null`: derrubaria a lista por uma imagem.                             |
| `listTypes`/`listGenerations` chamam `/type?limit=100` e `/generation` e filtram/rotulam pelo contrato           | Devolver as constantes do contrato: funciona, mas deixaria o filtro de 21 → 18 tipos (§2.3.3) sem exercício.             |
| Fixtures enxutas (`moves: []`, listas de Pokémon das habilidades vazias)                                         | Fixtures íntegras de 272 KB por Pokémon: peso no repositório sem ganho, pois os campos removidos não entram no contrato. |
| Cliente falso sintetiza `/pokemon/{id}` e `/evolution-chain/{id}` desconhecidos                                  | Gravar 1.025 Pokémon para testar a paginação: inviável; o sintético mantém o schema real.                                |

## Pendências e riscos conhecidos

- Primeira página fria dispara até 24 `GET /pokemon/{id}` (272 KB cada no servidor); o cache torna as próximas instantâneas. Documentado no README.
- Uma geração X futura faria `speciesDtoSchema` rejeitar a espécie (502) até o contrato ganhar o novo valor — falha explícita, não dado inventado.
