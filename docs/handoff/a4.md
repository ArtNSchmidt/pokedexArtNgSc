# Handoff A4 — API HTTP

## O que entreguei

- `application/useCases/`: `createUseCases(repository)` → `listPokemon`, `getPokemonDetail`, `listTypes`, `listGenerations`, `getHealth`. Cada caso de uso recebe a porta por parâmetro; nenhum instancia infraestrutura.
- `interface/http/validation.ts`: `parseOrThrow(schema, value)` valida query e params na borda; falha vira `RequestValidationError` (lista os campos inválidos, em PT-BR).
- `interface/http/errorHandler.ts`: **único** tradutor exceção → HTTP (§6.3): `RequestValidationError` → 400, `PokemonNotFoundError` → 404, `UpstreamUnavailableError` → 502 (mensagem genérica; detalhe só no log), erro 4xx do próprio Fastify → 400, resto → 500 genérico. `notFoundHandler` → 404 `ROUTE_NOT_FOUND`.
- `interface/http/routes/{health,catalog,pokemon}.routes.ts`: handlers de uma linha — validam, chamam o caso de uso, respondem.
- `interface/http/server.ts`: `buildServer({ useCases, logger })` registra CORS (`GET`, qualquer origem), error/not-found handlers, `Cache-Control: public, max-age=300` nas leituras 200 (exceto `/health`) e as rotas sob `/api/v1`. Não escuta.
- `main.ts`: composition root — cliente, índice, caches, repositório, casos de uso, servidor; aquece o índice (falha vira aviso e carga sob demanda); `PORT`/`HOST` por ambiente; `SIGTERM`/`SIGINT` fecham o Fastify.
- Testes: `server.test.ts` (10) com `FakePokemonRepository` via `app.inject`, sem rede.

## Decisões que tomei e a alternativa que descartei

| Decisão                                                                             | Alternativa descartada e por quê                                                                              |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Validação com **Zod do contrato** (`parseOrThrow`) em vez do JSON Schema do Fastify | Duplicar as regras de §6.1 em JSON Schema: dois lugares para divergir; o contrato já é a fonte.               |
| `ROUTE_NOT_FOUND` (404) acrescentado ao contrato via `docs/handoff/requests.md`     | Responder `POKEMON_NOT_FOUND` para `/nope`: mentira semântica; `INTERNAL_ERROR`: pior.                        |
| Mensagem de 400 lista só os **campos** inválidos (`Parâmetros inválidos: type.`)    | Repassar as mensagens do Zod: em inglês e com detalhes de implementação para o usuário.                       |
| Casos de uso como **fábricas** (`createListPokemon(repository)`) devolvendo funções | Classes com injeção: mais cerimônia para cinco funções de uma linha.                                          |
| Plugins de rota devolvem `Promise.resolve()` em vez de `async` sem `await`          | `async` vazio dispara `require-await`; `FastifyPluginCallback` obrigaria `done()` em todos.                   |
| Aquecimento do índice **tolerante a falha**                                         | Abortar o boot se a PokéAPI estiver fora: a API ficaria indisponível por um problema transitório do upstream. |

## Pendências e riscos conhecidos

- O `onSend` só marca `Cache-Control` em respostas 200; erros não são cacheáveis por desenho.
- `origin: true` no CORS reflete qualquer origem — adequado a uma API pública somente-leitura; se um dia houver escrita, restringir.
